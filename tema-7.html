Números reales en el ordenador

Un double guarda un número real con 52 bits de mantisa (fracción), 11 de exponente y 1 de signo. Un float, con 23, 8 y 1. Con un número finito de bits solo se pueden representar algunos valores: el resto se aproxima al más cercano.

La clave: igual que 1/3=0,333…1/3 = 0{,}333\ldots1/3=0,333… no cabe en decimal, 0,10{,}10,1 no cabe en binario:

0,110=0,0001 1001 1001 1001 1001 1001…20{,}1_{10} = 0{,}0001\,1001\,1001\,1001\,1001\,1001\ldots_20,110​=0,000110011001100110011001…2​

Es una fracción periódica infinita. Cualquier cantidad finita de bits la corta y comete un pequeño error.

CPP#include <cmath>
#include <cstdio>
#include <iostream>
using namespace std;

int main() {
    cout.precision(17);
    cout << "0.1 + 0.2 == 0.3 ? " << boolalpha << (0.1 + 0.2 == 0.3) << '\n';
    cout << "0.1 + 0.2 = " << 0.1 + 0.2 << '\n';
    cout << "|0.1+0.2-0.3| < 1e-9 ? " << (fabs(0.1 + 0.2 - 0.3) < 1e-9) << '\n';
    double s = 0;
    for (int i = 0; i < 10; ++i) s += 0.1;
    cout << "suma de diez 0.1 = " << s << " (== 1 ? " << (s == 1.0) << ")\n";

    // Reloj del Patriot: décimas de segundo como entero, 0,1 truncado a 23 bits tras la coma
    const double truncado = floor(0.1 * (1 << 23)) / (1 << 23);
    const double error_tic = 0.1 - truncado;
    const long tics = 100L * 3600 * 10;                  // 100 horas
    const double deriva = tics * error_tic;
    printf("error por tic   = %.3e s\n", error_tic);
    printf("deriva en 100 h = %.4f s\n", deriva);
    printf("desplazamiento  = %.0f m (Scud a 1676 m/s)\n", deriva * 1676);
}
Salida0.1 + 0.2 == 0.3 ? false
0.1 + 0.2 = 0.30000000000000004
|0.1+0.2-0.3| < 1e-9 ? true
suma de diez 0.1 = 0.99999999999999989 (== 1 ? false)
error por tic   = 9.537e-08 s
deriva en 100 h = 0.3433 s
desplazamiento  = 575 m (Scud a 1676 m/s)

Consecuencias prácticas:

  • Nunca compares double con ==. Compara con tolerancia: fabs(a - b) < 1e-9.
  • Los errores se acumulan: sumar 0,1 diez veces no da exactamente 1.
  • Sumar un número muy pequeño a uno muy grande lo pierde (los dígitos no caben).
  • Para dinero o tiempo, usa enteros (céntimos, microsegundos) o tipos de tiempo como std::chrono.

Qué suele fallar

  • Condiciones de bucle con double (while (x != 1.0)): puede no terminar nunca.
  • Convertir double a int trunca hacia cero (3,99 → 3), no redondea.
  • Dividir enteros: 1/2 es 0; escribe 1.0/2.
  • Restar dos números casi iguales: se pierden cifras significativas (cancelación).

Caso 1: el misil Patriot (Dhahran, 1991)

El reloj interno del Patriot contaba el tiempo en décimas de segundo como un entero. Para convertirlo a segundos multiplicaba por 1/101/101/10, almacenado con 24 bits y por tanto truncado. El error de cada tic era

e=0,1−⌊0,1⋅223⌋223≈9,5⋅10−8 s.e = 0{,}1 - \frac{\lfloor 0{,}1 \cdot 2^{23} \rfloor}{2^{23}} \approx 9{,}5\cdot 10^{-8}\ \text{s}.e=0,1−223⌊0,1⋅223⌋​≈9,5⋅10−8 s.

Parece diminuto, pero la batería llevaba unas 100 horas encendida, es decir, 100⋅3600⋅10=3,6⋅106100\cdot 3600\cdot 10 = 3{,}6\cdot 10^{6}100⋅3600⋅10=3,6⋅106 tics:

deriva=3,6⋅106⋅9,5⋅10−8≈0,34 s.\text{deriva} = 3{,}6\cdot 10^{6}\cdot 9{,}5\cdot 10^{-8} \approx 0{,}34\ \text{s}.deriva=3,6⋅106⋅9,5⋅10−8≈0,34 s.

Un Scud viaja a unos 1676 m/s, así que en 0,34 s se mueve más de medio kilómetro: el sistema miraba donde el misil ya no estaba y lo descartó como falsa alarma. (Con e=9,5⋅10−8e = 9{,}5\cdot10^{-8}e=9,5⋅10−8 exactos salen 573 m; con el valor sin redondear, 575 m: el orden de magnitud es lo importante.)

Lección

Un error pequeño y sistemático se vuelve grande con el tiempo. En tiempo real, el tiempo es lo que más se acumula. Por eso el tiempo se mide con enteros, o con tipos precisos, y los relojes se recalibran. Fuente de referencia: U.S. General Accounting Office, Patriot Missile Defense: Software Problem Led to System Failure at Dhahran, Saudi Arabia (IMTEC-92-26, 1992).

Caso 2: Mars Pathfinder (1997)

Pocos días después de aterrizar en Marte, el ordenador de la sonda empezó a reiniciarse solo. El sistema operativo era VxWorks, con planificación expulsiva por prioridades fijas. Las tareas que importan, de mayor a menor prioridad:

  1. bc_sched: planifica el bus de datos y comprueba con un watchdog que bc_dist terminó en el ciclo anterior.
  2. bc_dist: distribuye datos por el bus.
  3. Varias tareas de prioridad media (comunicaciones, etc.).
  4. ASI/MET: tarea científica de baja prioridad.

bc_dist y ASI/MET compartían una estructura protegida por un mutex. La secuencia fatal fue la inversión de prioridad que ya conoces:

  1. ASI/MET toma el mutex.
  2. bc_dist (alta) se bloquea esperándolo.
  3. Tareas medias expulsan a ASI/MET, así que bc_dist espera cuanto ellas quieran.
  4. bc_sched detecta que bc_dist no ha terminado y reinicia el sistema.

La solución fue activar la herencia de prioridad en el mutex (estaba desactivada por rendimiento). Se pudo hacer desde la Tierra, actualizando parámetros, porque el sistema conservaba sus herramientas de trazas. Puedes reproducir el efecto en el simulador de T6 (sin protocolo frente a herencia o techo).

Más a fondo

El protocolo de herencia y el de techo de prioridad se deben a L. Sha, R. Rajkumar y J. Lehoczky, «Priority Inheritance Protocols: An Approach to Real-Time Synchronization», IEEE Trans. on Computers, 1990. La explicación de lo ocurrido en Pathfinder circuló en el foro RISKS Digest (vol. 19, n.º 49, 1997). Sobre aritmética de coma flotante, la referencia clásica es D. Goldberg, «What Every Computer Scientist Should Know About Floating-Point Arithmetic», ACM Computing Surveys, 1991.

Coma flotante

  • double: 1 bit de signo + 11 de exponente + 52 de mantisa (≈ 15-16 cifras decimales).
  • float: 1 + 8 + 23 (≈ 7 cifras decimales).
  • Comparar: fabs(a - b) < tolerancia.
  • Error acumulado ≈ (error por operación) × (número de operaciones).
  • Patriot: e=0,1−⌊0,1⋅223⌋/223≈9,5⋅10−8e = 0{,}1 - \lfloor 0{,}1\cdot 2^{23}\rfloor / 2^{23} \approx 9{,}5\cdot 10^{-8}e=0,1−⌊0,1⋅223⌋/223≈9,5⋅10−8 s; en 100 h: 0,34 s.

Experimentos con coma flotante

Cuatro experimentos que explican por qué falla == con reales y cómo evitarlo.

CPP#include <cmath>
#include <iomanip>
#include <iostream>
#include <vector>
using namespace std;

bool casi_igual(double a, double b, double rel = 1e-9) {          // tolerancia RELATIVA: funciona con números grandes y pequeños
    return fabs(a - b) <= rel * max(fabs(a), fabs(b));
}

int main() {
    cout << setprecision(10);
    const int N = 10'000'000;
    float sf = 0; double sd = 0;
    for (int i = 0; i < N; ++i) { sf += 0.1f; sd += 0.1; }
    // Kahan: guarda en 'c' lo que se pierde en cada suma y lo recupera en la siguiente
    double s = 0, c = 0;
    for (int i = 0; i < N; ++i) { double y = 0.1 - c; double t = s + y; c = (t - s) - y; s = t; }
    cout << "suma de 0,1 diez millones de veces (exacto: 1000000)\n";
    cout << "  float : " << sf << "\n  double: " << sd << "\n  Kahan : " << s << '\n';

    cout << "\nUn bucle con paso 0,1 y == nunca para exactamente en 1:\n";
    int vueltas = 0;
    for (double x = 0; x < 1.0 - 1e-9 && vueltas < 20; x += 0.1) ++vueltas;
    cout << "  con tolerancia: " << vueltas << " vueltas\n";
    double x = 0; for (int i = 0; i < 10; ++i) x += 0.1;
    cout << boolalpha << "  tras 10 sumas, x == 1.0 ? " << (x == 1.0) << " ; x = " << setprecision(17) << x << '\n';
    cout << setprecision(10);

    cout << "\nComparar con tolerancia absoluta frente a relativa:\n";
    double a = 1e12, b = 1e12 + 0.0001;
    cout << "  fabs(a-b) < 1e-9 : " << (fabs(a - b) < 1e-9) << " (falla: a y b son casi iguales)\n";
    cout << "  casi_igual(a,b)  : " << casi_igual(a, b) << '\n';

    cout << "\nOrden de suma: sumar de menor a mayor pierde menos\n";
    vector<float> v;
    v.push_back(1e8f);
    for (int i = 0; i < 100; ++i) v.push_back(1.0f);
    float mayor_primero = 0, menor_primero = 0;
    for (float t : v) mayor_primero += t;
    for (auto it = v.rbegin(); it != v.rend(); ++it) menor_primero += *it;
    cout << "  1e8 + cien unos, mayor primero: " << mayor_primero << " ; menor primero: " << menor_primero << " (exacto 100000100)\n";
}
Salidasuma de 0,1 diez millones de veces (exacto: 1000000)
  float : 1087937
  double: 999999.9998
  Kahan : 1000000

Un bucle con paso 0,1 y == nunca para exactamente en 1:
  con tolerancia: 10 vueltas
  tras 10 sumas, x == 1.0 ? false ; x = 0.99999999999999989

Comparar con tolerancia absoluta frente a relativa:
  fabs(a-b) < 1e-9 : false (falla: a y b son casi iguales)
  casi_igual(a,b)  : true

Orden de suma: sumar de menor a mayor pierde menos
  1e8 + cien unos, mayor primero: 100000000 ; menor primero: 100000096 (exacto 100000100)

Qué enseña cada salida

  1. Sumar 0,1 diez millones de veces: float da 1 087 937 (error del 9 %), double da 999 999,9998 y Kahan da 1 000 000 exacto. Kahan guarda en c lo que se pierde en cada suma y lo recupera en la siguiente.
  2. Bucle con paso 0,1: tras 10 sumas, x vale 0,99999999999999989, no 1; con tolerancia el bucle da exactamente 10 vueltas. Por eso x == 1.0 es falso y un bucle while (x != 1.0) no termina. Usa < con margen o cuenta con un entero.
  3. Tolerancia absoluta frente a relativa: con números grandes, fabs(a-b) < 1e-9 da false aunque a y b sean prácticamente iguales; casi_igual compara la diferencia con una fracción del valor (rel * max(|a|,|b|)) y da true.
  4. Orden de suma: 10810^8108 más cien unos da 100 000 000 si sumas primero el grande (los unos se pierden) y 100 000 096 si sumas primero los pequeños (exacto: 100 000 100). De menor a mayor se pierde menos.

Qué suele fallar

  • if (x == 0.3) o while (x != 1.0) con reales: casi siempre un error.
  • Mezclar int y double: 1/2 vale 0; escribe 1.0/2.
  • Restar números casi iguales (cancelación): se pierden cifras significativas. Reformula la fórmula si puedes.
  • Esperar que float tenga más de 7 cifras: a partir de ahí los números no son exactos.

Regla práctica

Si vas a comparar reales: tolerancia relativa. Si vas a sumar muchos: de pequeño a grande, o con Kahan. Si necesitas contar: entero.
