C++ moderno: de los objetos a la concurrencia · Tema 3

Programación basada en objetos

C++ moderno: de los objetos a la concurrenciaProgramación

Desde cero

Objetivo: escribir clases bien formadas: atributos privados, constructores, métodos const, sobrecarga de operadores y gestión de recursos.

  • La programación basada en objetos (PBO) es usar clases para agrupar datos y las operaciones que actúan sobre ellos, sin herencia todavía. La herencia y el polimorfismo son el tema siguiente, y juntos forman la POO.
  • Una clase define un tipo nuevo: sus atributos (el estado) y sus métodos (el comportamiento). La regla de oro es el encapsulamiento: los atributos van private y el acceso pasa por métodos públicos. Así la clase puede garantizar que su estado es siempre válido.
  • El constructor se llama al crear el objeto y su trabajo es dejarlo en un estado válido. Puede haber varios (sobrecarga): por defecto, con parámetros, de copia. Si no escribes ninguno, el compilador genera uno por defecto; si escribes cualquiera, deja de generarlo.
  • La lista de inicialización (: x_(x), y_(y)) inicializa los atributos antes de entrar en el cuerpo del constructor. Es más eficiente que asignar dentro y es obligatoria para constantes y referencias.
  • El destructor ~Clase() se llama al destruirse el objeto y sirve para liberar lo que la clase haya reservado. De ahí sale el patrón RAII: adquirir el recurso en el constructor y liberarlo en el destructor, de modo que nunca se olvide. Es exactamente lo que hacen lock_guard y los flujos de fichero.
  • Un método que no modifica el objeto se marca const: int get_x() const;. Sólo sobre un objeto constante se pueden llamar métodos const, así que marcarlos bien es lo que permite pasar objetos por const&.
  • this es un puntero al objeto sobre el que se invoca el método. Se usa cuando hay que devolver *this o distinguir un parámetro de un atributo con el mismo nombre.
  • Los operadores se pueden sobrecargar para que los objetos se comporten como tipos nativos: +, ==, <, y sobre todo << y >> para imprimir y leer. operator<< no puede ser método de la clase porque su operando izquierdo es el flujo: se declara función libre, normalmente friend.

Explicación ampliada

Clase, objeto y constructor

Una clase es un molde: agrupa atributos (datos) y métodos (funciones que trabajan con ellos). Un objeto es una pieza fabricada con ese molde. Los atributos se declaran private (nadie de fuera los toca) y se ofrece acceso con métodos get/set (los get son const: prometen no modificar el objeto). Un constructor inicializa el objeto al crearlo (por defecto, con parámetros, de copia) y se escribe con lista de inicialización (Punto(double x,double y) : x_(x), y_(y) {}); el destructor ~Punto() se ejecuta al destruirlo.

Sobrecarga de operadores y orden de vida

Puedes enseñar a tu clase a usar los operadores normales: operator+ para sumar dos puntos, operator== para compararlos, operator<< (como función amiga) para imprimirlos con cout. Regla útil para trazar un programa: los objetos se construyen en el orden en que se declaran y se destruyen en orden inverso (el último en crearse es el primero en destruirse). Al copiar (Punto c(b); o pasar por valor) se llama al constructor de copia; si la clase tiene punteros, hay que escribir uno propio (copia profunda) o dos objetos compartirían la misma memoria.

Fórmulas y conceptos que hay que saber

  • Esqueleto de una clase:
class Punto { double x_, y_; // atributos privados public: Punto() : x_(0), y_(0) {} // por defecto Punto(double x, double y) : x_(x), y_(y) {} // con parámetros Punto(const Punto &p) : x_(p.x_), y_(p.y_) {} // de copia ~Punto() {} // destructor double get_x() const { return x_; } // método const void set_x(double x) { x_ = x; } double modulo() const { return sqrt(x_*x_ + y_*y_); } Punto operator+(const Punto &p) const { return Punto(x_+p.x_, y_+p.y_); } bool operator==(const Punto &p) const { return x_==p.x_ && y_==p.y_; } friend ostream& operator<<(ostream &os, const Punto &p); }; ostream& operator<<(ostream &os, const Punto &p) { os << "(" << p.x_ << ", " << p.y_ << ")"; return os; // devolver el flujo permite encadenar }
  • Orden de llamadas: constructor → vida del objeto → destructor. Los objetos de la pila se destruyen en orden inverso al de creación, al salir del ámbito.
  • Regla de los tres (clásica): si una clase necesita destructor, casi seguro necesita también constructor de copia y operador de asignación. Pasa siempre que la clase reserva memoria con new.
  • static: un atributo o método static pertenece a la clase, no a cada objeto. Útil para contadores de instancias.
  • Miembros constantes: const int id_; obliga a inicializar en la lista, nunca en el cuerpo.

Método paso a paso

  1. Identifica el estado que la clase debe guardar y hazlo private.
  2. Escribe los constructores que necesite el enunciado, siempre con lista de inicialización.
  3. Marca const todos los métodos que no modifiquen el objeto, empezando por los getters.
  4. Si la clase reserva memoria, escribe destructor, constructor de copia y operator=; si no reserva nada, no escribas ninguno y deja los del compilador.
  5. Sobrecarga los operadores que el enunciado pida; operator<< como función libre que devuelve el flujo.
  6. Prueba la clase con un main pequeño que cree objetos, los copie, los imprima y compruebe el resultado.

Trampas típicas

  • Poner los atributos public «para no escribir getters». Rompe el encapsulamiento y es lo primero que se penaliza.
  • Asignar en el cuerpo del constructor en lugar de usar la lista de inicialización: con atributos constantes o referencias ni siquiera compila.
  • Olvidar el const en los métodos de consulta: luego no se puede llamar a esos métodos sobre un const Punto& y el código no compila.
  • Escribir operator<< como método de la clase: el operando izquierdo tiene que ser el ostream.
  • Que operator<< no devuelva el flujo: entonces no se puede encadenar cout << a << b.
  • Reservar con new en el constructor y no liberar en el destructor, o liberar dos veces al copiar el objeto sin un constructor de copia propio.

Problema resuelto

Enunciado

Diseña una clase Alumno con nombre, número de expediente y un vector de notas. Debe permitir añadir notas, calcular la media, comparar alumnos por media e imprimirse con cout. Escribe también un main que lea los alumnos de un fichero y muestre el de mejor media.

✓Ver solución paso a paso
#include <iostream> #include <fstream> #include <sstream> #include <string> #include <vector> using namespace std; class Alumno { string nombre_; int expediente_; vector<double> notas_; public: Alumno() : expediente_(0) {} Alumno(const string &n, int e) : nombre_(n), expediente_(e) {} const string& get_nombre() const { return nombre_; } int get_expediente() const { return expediente_; } void add_nota(double n) { notas_.push_back(n); } double media() const { if (notas_.empty()) return 0.0; double s = 0.0; for (double n : notas_) s += n; return s / notas_.size(); } bool operator<(const Alumno &a) const { return media() < a.media(); } friend ostream& operator<<(ostream &os, const Alumno &a); }; ostream& operator<<(ostream &os, const Alumno &a) { os << a.expediente_ << " - " << a.nombre_ << " (media " << a.media() << ")"; return os; } int main() { ifstream f("alumnos.txt"); // formato: expediente;nombre;n1 n2 n3 if (!f) { cerr << "No se pudo abrir\n"; return 1; } vector<Alumno> v; string linea; while (getline(f, linea)) { stringstream ss(linea); string exp, nom, notas; getline(ss, exp, ';'); getline(ss, nom, ';'); getline(ss, notas); Alumno a(nom, stoi(exp)); stringstream sn(notas); double x; while (sn >> x) a.add_nota(x); v.push_back(a); } if (v.empty()) { cout << "Sin alumnos\n"; return 0; } const Alumno *mejor = &v[0]; for (const Alumno &a : v) if (*mejor < a) mejor = &a; cout << "Mejor media: " << *mejor << endl; return 0; }

Decisiones que hay que saber justificar.

  • Los tres atributos son privados y se accede por métodos. get_nombre devuelve const string&: no copia y no deja modificar.
  • media() y operator< son const: no cambian el objeto, y por eso se pueden llamar sobre el const Alumno& del bucle.
  • No hay destructor ni constructor de copia: la clase no reserva memoria, el vector se encarga de la suya. Escribirlos aquí sería trabajo de más y una fuente de errores.
  • Para trocear por ; se usa getline con delimitador sobre un stringstream; para las notas, el >> de siempre.
  • Se guarda un puntero al mejor, no una copia, para no copiar el vector de notas en cada comparación.

El patrón «leer fichero → trocear línea → construir objeto → meter en vector → recorrer el vector» es el esqueleto de la mitad de los ejercicios de programación del examen. Tenlo escrito de memoria y sólo cambia la clase.

Ejercicio 1 · Constructores y destructores

Punto a;            // por defecto
Punto b(1, 2);      // con parámetros
Punto c(b);         // de copia

¿En qué orden se construyen y se destruyen?

✓Ver solución paso a paso

Construcción: a (por defecto), b (parámetros), c (copia). Al salir del ámbito, destrucción en orden inverso: c, b, a. Un total de 3 constructores y 3 destructores.

Ejercicio 2 · Sobrecarga de operador + y módulo

Con operator+ definido como en la teoría, ¿qué vale Punto(1,2)+Punto(3,4) y su modulo()?

✓Ver solución paso a paso

Suma componente a componente: \((1+3,\,2+4)=(4{,}6)\). Módulo \(=\sqrt{4^2+6^2}=\sqrt{52}=7{,}211\).

Ejercicio 3 · Qué compila con const

En void f(const Punto &p) { p.set_x(1); double d = p.get_x(); }, ¿qué línea falla y por qué?

✓Ver solución paso a paso

Falla p.set_x(1): p es constante y set_x no es const, así que podría modificar el objeto y el compilador lo impide. p.get_x() sí compila porque get_x está declarado const. Por eso los métodos de solo lectura se marcan siempre const.

Autoevaluación

Responde antes de desplegar.

1¿Qué significa encapsular?

Mantener los atributos private y dar acceso sólo por métodos públicos, de modo que la clase garantice siempre un estado válido.

2¿Para qué sirve la lista de inicialización de un constructor?

Para inicializar los atributos antes del cuerpo. Es más eficiente y es obligatoria con atributos constantes o referencias.

3¿Qué es RAII?

Adquirir un recurso en el constructor y liberarlo en el destructor, de modo que no pueda quedarse sin liberar. Lo usan lock_guard y los flujos de fichero.

4¿Qué indica const al final de un método?

Que el método no modifica el objeto. Sólo esos métodos pueden llamarse sobre un objeto constante.

5¿Por qué operator<< no puede ser método de la clase?

Porque su operando izquierdo es el ostream, no el objeto. Se declara como función libre, normalmente friend.

6¿Qué dice la regla de los tres?

Que si una clase necesita destructor, también necesita constructor de copia y operador de asignación propios.
