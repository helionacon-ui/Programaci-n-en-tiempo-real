Qué hay que decidir: quién ejecuta y cuándo

Con una sola CPU y varias tareas con plazos, hace falta una política de planificación. Después hay que demostrar (no probar) que todas cumplen sus plazos incluso en el peor caso. Hay dos familias:

  • Planificación estática (ejecutivo cíclico): el plan se calcula antes de ejecutar y se repite.
  • Planificación por prioridades con expulsión: cada tarea tiene una prioridad; si llega una más prioritaria, expulsa a la que está ejecutando.

Notación (la misma de T0): cada tarea iii tiene cómputo CiC_iCi​, periodo TiT_iTi​ y plazo Di≤TiD_i \le T_iDi​≤Ti​.

Ejecutivo cíclico

Si todas las tareas son periódicas, el comportamiento se repite cada ciclo principal TM=mcm(Ti)T_M = \mathrm{mcm}(T_i)TM​=mcm(Ti​) (el hiperperiodo). Se divide en ciclos secundarios de duración TST_STS​ y en cada uno se ejecutan unas tareas, sin interrupciones. Entre ciclos se espera con sleep_until.

Condiciones para elegir TST_STS​:

  1. TST_STS​ divide a TMT_MTM​ (el ciclo principal es un número entero de secundarios).
  2. TS≥max⁡CiT_S \ge \max C_iTS​≥maxCi​ (así ninguna tarea se parte; si no, hay que trocear tareas).
  3. Para cada tarea, entre su activación y su plazo debe caber un ciclo secundario completo: 2TS−gcd⁡(TS,Ti)≤Di2T_S - \gcd(T_S, T_i) \le D_i2TS​−gcd(TS​,Ti​)≤Di​.

El código es un bucle con switch (ciclo) y sleep_until:

CPPauto siguiente = steady_clock::now() + ts;
int ciclo = 0;
while (true) {
    switch (ciclo) {                      // plan estático del ciclo principal
        case 0: A(); B(); C(); break;
        case 1: A(); break;
        /* ... */
    }
    ciclo = (ciclo + 1) % N_CICLOS;
    this_thread::sleep_until(siguiente);   // instante absoluto: sin deriva
    siguiente += ts;
}

Ventajas: simple y predecible. Inconvenientes: rígido, difícil con tareas esporádicas y con periodos «incómodos» (hiperperiodo enorme).

Prioridades fijas: RM y DM

  • RM (Rate Monotonic): menor periodo ⇒ mayor prioridad. Óptimo cuando Di=TiD_i = T_iDi​=Ti​.
  • DM (Deadline Monotonic): menor plazo ⇒ mayor prioridad. Óptimo cuando Di≤TiD_i \le T_iDi​≤Ti​ (incluye RM).

Dos formas de comprobar la planificabilidad:

1. Condición suficiente (rápida, pero pesimista). Para nnn tareas con D=TD=TD=T (Liu y Layland):

U=∑i=1nCiTi≤n(21/n−1)U = \sum_{i=1}^{n} \frac{C_i}{T_i} \le n\left(2^{1/n} - 1\right)U=i=1∑n​Ti​Ci​​≤n(21/n−1)

La cota baja de 1 (n=1) a ln⁡2≈0,693\ln 2 \approx 0{,}693ln2≈0,693 cuando n→∞n \to \inftyn→∞. Si UUU la cumple, el conjunto es planificable. Si no, no se puede concluir nada.

2. Tiempo de respuesta (exacta). El tiempo de respuesta RiR_iRi​ es el máximo desde que iii se activa hasta que termina. Se calcula iterando:

Ri(0)=Ci+Bi,Ri(k+1)=Ci+Bi+∑j∈hp(i)⌈Ri(k)Tj⌉CjR_i^{(0)} = C_i + B_i,\qquad R_i^{(k+1)} = C_i + B_i + \sum_{j \in hp(i)} \left\lceil \frac{R_i^{(k)}}{T_j} \right\rceil C_jRi(0)​=Ci​+Bi​,Ri(k+1)​=Ci​+Bi​+j∈hp(i)∑​⌈Tj​Ri(k)​​⌉Cj​

hasta que Ri(k+1)=Ri(k)R_i^{(k+1)} = R_i^{(k)}Ri(k+1)​=Ri(k)​ (converge) o se pasa de DiD_iDi​ (no planificable). hp(i)hp(i)hp(i) son las tareas de mayor prioridad y BiB_iBi​ es el bloqueo (más abajo, vale 0 sin recursos compartidos). La tarea cumple si Ri≤DiR_i \le D_iRi​≤Di​.

Intuición

El tiempo de respuesta es «mi trabajo + el trabajo de los más prioritarios que llegan mientras espero». Cada vez que sumo trabajo ajeno, tardo más, y puede entrar otra activación de una tarea más prioritaria. La iteración busca el punto fijo.

Ejemplo: (C,T)=(3,7),(3,12),(5,20)(C,T)=(3,7),(3,12),(5,20)(C,T)=(3,7),(3,12),(5,20) con D=TD=TD=T. Es U=0,929>0,780U = 0{,}929 > 0{,}780U=0,929>0,780, así que la cota no sirve, pero el tiempo de respuesta sí concluye:

Recursos compartidos: inversión de prioridad

Una tarea baja (L) toma un mutex. Llega una alta (H) que lo necesita: se bloquea. Hasta aquí, normal. Pero si ahora llega una media (M) que no usa el recurso, M expulsa a L (tiene más prioridad que L) y H sigue esperando a M, que tiene menos prioridad que H. Eso es la inversión de prioridad: la espera de H no está acotada por la sección crítica de L, sino por todo lo que haga M.

Dos protocolos que la resuelven:

ProtocoloReglaBloqueo
Herencia de prioridadSi H se bloquea por L, L hereda la prioridad de H mientras tenga el recursoPuede haber bloqueo en cadena; interbloqueo posible
Techo de prioridad inmediato (ICPP)Cada recurso tiene un techo = prioridad máxima de las tareas que lo usan. Al tomar el recurso, la tarea sube a ese techoUna tarea se bloquea como mucho una vez y como mucho una sección crítica; sin interbloqueos

Cálculo con ICPP

  1. Prioridades (DM o RM).
  2. Techo de cada recurso: máximo de las prioridades de las tareas que lo usan.
  3. Bloqueo de la tarea iii:

Bi=max⁡{ ck,r  :  k de menor prioridad que i, r con techo(r)≥Pi }B_i = \max \{\, c_{k,r} \;:\; k \text{ de menor prioridad que } i,\ r \text{ con techo}(r) \ge P_i \,\}Bi​=max{ck,r​:k de menor prioridad que i, r con techo(r)≥Pi​}

donde ck,rc_{k,r}ck,r​ es la duración máxima de la sección crítica de kkk sobre rrr. La tarea de menor prioridad tiene B=0B=0B=0 y nunca se bloquea por una de menor prioridad.

  1. Tiempo de respuesta con BiB_iBi​ en la recurrencia.

Qué suele fallar

  • Tomar secciones críticas de tareas de mayor o igual prioridad en BiB_iBi​: solo cuentan las de menor prioridad.
  • Incluir recursos cuyo techo es menor que la prioridad de la tarea: no la bloquean (el techo es lo que lo decide, no quién usa el recurso).
  • Olvidar que el plazo de una tarea esporádica es DDD y su periodo mínimo TTT: se analiza igual, con TTT como separación mínima.
  • Parar la iteración en la primera vuelta: hay que repetir hasta que el valor no cambie.
  • Mezclar «prioridad más alta» con «número más grande»: fija la convención (aquí, mayor número = mayor prioridad).

EDF y utilización

EDF (Earliest Deadline First) da la prioridad a la tarea cuyo plazo absoluto es más próximo. Con D=TD=TD=T y una CPU, el conjunto es planificable si y solo si U≤1U \le 1U≤1 (Liu y Layland, 1973). Es más eficiente que RM, pero las prioridades cambian en tiempo de ejecución y el análisis con recursos es más complejo.

Más a fondo

La cota n(21/n−1)n(2^{1/n}-1)n(21/n−1) sale de buscar el peor reparto de periodos para el que RM aún funciona: para n=2n=2n=2 es 0,8280{,}8280,828, para n=3n=3n=3 es 0,7800{,}7800,780. Es solo suficiente: el conjunto (3,7),(3,12),(5,20)(3,7),(3,12),(5,20)(3,7),(3,12),(5,20) tiene U=0,929U=0{,}929U=0,929 y es planificable. Referencias: C. L. Liu y J. W. Layland, «Scheduling Algorithms for Multiprogramming in a Hard-Real-Time Environment», J. ACM, 1973; A. Burns y A. Wellings, Real-Time Systems and Programming Languages.

Planificación: fórmulas clave

  • Utilización: U=∑Ci/TiU = \sum C_i/T_iU=∑Ci​/Ti​.
  • Cota RM (D=T): U≤n(21/n−1)U \le n(2^{1/n}-1)U≤n(21/n−1) — n=1: 1n=1{:}\,1n=1:1; n=2: 0,828n=2{:}\,0{,}828n=2:0,828; n=3: 0,780n=3{:}\,0{,}780n=3:0,780.

  • Ciclo secundario: TS∣TMT_S \mid T_MTS​∣TM​, TS≥max⁡CiT_S \ge \max C_iTS​≥maxCi​, 2TS−gcd⁡(TS,Ti)≤Di2T_S - \gcd(T_S,T_i) \le D_i2TS​−gcd(TS​,Ti​)≤Di​.
  • Tiempo de respuesta: Ri=Ci+Bi+∑j∈hp(i)⌈Ri/Tj⌉CjR_i = C_i + B_i + \sum_{j\in hp(i)} \lceil R_i/T_j \rceil C_jRi​=Ci​+Bi​+∑j∈hp(i)​⌈Ri​/Tj​⌉Cj​.

Cuando RM falla y EDF no: ejemplo explicado

Dos tareas, τ1=(C=2,T=5)\tau_1=(C{=}2,T{=}5)τ1​=(C=2,T=5) y τ2=(C=4,T=7)\tau_2=(C{=}4,T{=}7)τ2​=(C=4,T=7). La utilización es U=0,4+0,571=0,971U=0{,}4+0{,}571=0{,}971U=0,4+0,571=0,971.

  • Test de utilización RM: 0,971>0,8280{,}971>0{,}8280,971>0,828. El test no decide.
  • Tiempo de respuesta de τ2\tau_2τ2​: R=4→4+⌈4/5⌉2=6→4+⌈6/5⌉2=8>7R=4\to4+\lceil4/5\rceil2=6\to4+\lceil6/5\rceil2=8>7R=4→4+⌈4/5⌉2=6→4+⌈6/5⌉2=8>7. No es planificable con RM.
  • EDF: U≤1U\le1U≤1 ⇒ sí es planificable.

El programa de abajo lo confirma simulando un hiperperiodo (35 unidades de tiempo). Con RM, τ2\tau_2τ2​ no acaba antes de su siguiente liberación en t=7t=7t=7.

CPP#include <algorithm>
#include <iostream>
#include <numeric>
#include <vector>
using namespace std;

struct Tarea { int C, T; };

// Simulación por unidades de tiempo. politica: 0 = RM (menor periodo primero), 1 = EDF (plazo más cercano primero)
int simular(const vector<Tarea>& ts, int politica, int horizonte, vector<string>& log) {
    int n = ts.size(), fallos = 0;
    vector<int> resta(n, 0), plazo(n, 0);
    for (int t = 0; t < horizonte; ++t) {
        for (int i = 0; i < n; ++i) {
            if (t % ts[i].T == 0) {                       // nueva liberación
                if (resta[i] > 0) { ++fallos; log.push_back("t=" + to_string(t) + ": tau" + to_string(i + 1) + " NO terminó antes de su nuevo periodo"); }
                resta[i] = ts[i].C; plazo[i] = t + ts[i].T;
            }
        }
        int mejor = -1;
        for (int i = 0; i < n; ++i) {
            if (resta[i] == 0) continue;
            if (mejor < 0 || (politica == 0 ? ts[i].T < ts[mejor].T : plazo[i] < plazo[mejor])) mejor = i;
        }
        if (mejor >= 0) --resta[mejor];
    }
    return fallos;
}

int main() {
    vector<Tarea> ts{{2, 5}, {4, 7}};
    double U = 0;
    for (auto& t : ts) U += double(t.C) / t.T;
    int H = lcm(5, 7);
    cout << "U = " << U << " (<= 1: EDF puede) ; cota RM n=2 = 0.828 (U la supera: RM no es seguro)\n";
    // Tiempo de respuesta de tau2 con RM: R = 4 + ceil(R/5)*2
    int R = 4;
    cout << "R2 (RM):";
    for (;;) { cout << ' ' << R; int nuevo = 4 + ((R + 4) / 5) * 2; if (nuevo == R || nuevo > 7) { if (nuevo != R) cout << ' ' << nuevo << " > D=7 -> NO planificable con RM"; break; } R = nuevo; }
    cout << '\n';
    vector<string> log;
    cout << "Simulación de " << H << " unidades:\n";
    cout << " RM : fallos = " << simular(ts, 0, H, log) << '\n';
    for (auto& l : log) cout << "      " << l << '\n';
    log.clear();
    cout << " EDF: fallos = " << simular(ts, 1, H, log) << '\n';
}

Receta: ¿es planificable? (el orden que da más puntos)

  1. Calcula UUU. Si U>1U>1U>1: no es planificable con ningún algoritmo. Fin.
  2. RM, test de la cota n(21/n−1)n(2^{1/n}-1)n(21/n−1). Si U≤U\leU≤ cota: sí. Si no, no concluye: sigue.
  3. Tiempo de respuesta, tarea por tarea, de mayor a menor prioridad. Si todas cumplen Ri≤DiR_i\le D_iRi​≤Di​: sí. Si una no: no con RM.
  4. EDF (con D=TD=TD=T): U≤1U\le1U≤1 ⇒ sí.
  5. Con recursos: calcula BiB_iBi​ con los techos y repite el paso 3 sumando BiB_iBi​.

Trucos de cálculo a mano

  • Techo rápido: ⌈R/T⌉\lceil R/T\rceil⌈R/T⌉ es «cuántas veces cabe TTT en RRR, redondeando hacia arriba». Si R=TR=TR=T exacto, sale 1, no 2.
  • Arranca la iteración en R(0)=Ci+BiR^{(0)}=C_i+B_iR(0)=Ci​+Bi​ y para cuando dos valores seguidos coinciden o cuando pasas de DiD_iDi​.
  • Prioridades RM: ordena por periodo (menor = más prioridad). Si dos coinciden, el enunciado decide el desempate.
  • Hiperperiodo: mcm⁡(Ti)\operatorname{mcm}(T_i)mcm(Ti​). Con periodos 555 y 777 es 353535; si son muchos, factoriza.

Qué suele fallar

  • Aplicar el test de utilización de RM a D<TD<TD<T. Solo vale con plazo igual a periodo.
  • Usar ⌊⋅⌋\lfloor\cdot\rfloor⌊⋅⌋ en vez de ⌈⋅⌉\lceil\cdot\rceil⌈⋅⌉ en la recurrencia.
  • Olvidar el bloqueo BiB_iBi​ de las tareas intermedias con ICPP: aunque τ2\tau_2τ2​ no use el recurso, sufre bloqueo si su techo es ≥P2\ge P_2≥P2​.
  • Declarar «no planificable» solo porque UUU supera la cota. La cota es suficiente, no necesaria: hay que mirar el tiempo de respuesta.
