Cómo usarlos

  1. Pon un temporizador de 75 minutos por ejercicio (150 min para el simulacro completo).
  2. Si el programa no compila, la nota de ese ejercicio se divide por 2 en el examen reciente: compila siempre antes de dar por bueno.
  3. Al terminar, abre los pasos y compara. Anota qué te ha fallado en la lista de «Qué suele fallar» del tema.

Revisor de código

Pega tu solución (se revisa mientras escribes): el revisor busca los fallos que más se repiten en los exámenes (falta de override, destructor no virtual, if en lugar de while en una espera, wait sin predicado, lock_guard con wait, falta de ref() al crear el hilo, hilos sin join, operator<< sin friend, consultas sin const, #include que faltan, ; después de la clase…). Simulacro 1 · Biblioteca y parking

Simulacro 1 · Ejercicio 1: préstamos de una biblioteca (POO, 70 %) herenciasimulacro

Enunciado

Una biblioteca presta libros y DVD. Todo elemento tiene título y año, un número de días de préstamo y una multa por día de retraso.

  1. Diseña una clase base abstracta Item con título, año, dias_prestamo() y multa_por_dia() (virtuales puros). Los libros (14 días, 0,50 €/día) guardan además las páginas; los DVD (7 días, 1 €/día), los minutos.
  2. Sobrecarga operator<< para que todo elemento se imprima con su título, año y días, y cada hija añada sus datos sin repetir el código de la base.
  3. Diseña Biblioteca, que guarda los elementos en un vector con punteros inteligentes y permite: añadir; calcular la multa de un título por unos días de retraso; devolver el elemento de mayor multa diaria; contar cuántos hay de un tipo (con typeid) y eliminar un título.
  4. Escribe un main que pruebe todo.

Antes de empezar: qué piden y qué teoría usas

Qué piden. Herencia con clase abstracta, polimorfismo (colección de punteros a la base), operator<< con gancho virtual, y algoritmos STL con lambdas.

Teoría que usas. T3: clase abstracta, destructor virtual, override, unique_ptr en vector, max_element, remove_if + erase, typeid.

1 1. La base abstracta

El destructor es virtual (se borran objetos hijos a través de la base). Los métodos de política son virtuales puros. operator<< es friend y delega en un método protegido virtual imprimir, que las hijas reutilizan llamando a Item::imprimir.

CPPclass Item {
public:
    Item(string titulo, int anio) : titulo_{move(titulo)}, anio_{anio} {}
    virtual ~Item() = default;                          // destructor virtual: se borra a través de la base
    virtual double multa_por_dia() const = 0;           // virtual puro: Item es abstracta
    virtual int dias_prestamo() const = 0;
    const string& titulo() const { return titulo_; }
    friend ostream& operator<<(ostream& os, const Item& i) { i.imprimir(os); return os; }
protected:
    virtual void imprimir(ostream& os) const {          // gancho reutilizable por las hijas
        os << '"' << titulo_ << "\" (" << anio_ << "), " << dias_prestamo() << " dias";
    }
private:
    string titulo_;
    int anio_;
};

3 3. Biblioteca
  • find_if con lambda para localizar un título (si no hay, o los días no son positivos, la multa es 0).
  • max_element con comparador sobre multa_por_dia().
  • typeid(*p) == t compara el tipo dinámico; typeid(p) sería el del puntero.
  • remove_if mueve los elementos que se mantienen al principio; erase borra la cola. Con unique_ptr, la memoria se libera sola.
CPPclass Biblioteca {
public:
    void anadir(unique_ptr<Item> i) { items_.push_back(move(i)); }
    double multa(const string& titulo, int dias_tarde) const {
        auto it = find_if(items_.begin(), items_.end(), [&](const auto& p) { return p->titulo() == titulo; });
        if (it == items_.end() || dias_tarde <= 0) return 0;
        return (*it)->multa_por_dia() * dias_tarde;
    }
    const Item* mayor_multa() const {
        auto it = max_element(items_.begin(), items_.end(),
                              [](const auto& a, const auto& b) { return a->multa_por_dia() < b->multa_por_dia(); });
        return it == items_.end() ? nullptr : it->get();
    }
    int contar(const type_info& t) const {
        return count_if(items_.begin(), items_.end(), [&](const auto& p) { return typeid(*p) == t; });
    }
    bool eliminar(const string& titulo) {
        auto it = remove_if(items_.begin(), items_.end(), [&](const auto& p) { return p->titulo() == titulo; });
        bool borrado = it != items_.end();
        items_.erase(it, items_.end());                 // unique_ptr libera la memoria solo
        return borrado;
    }
    friend ostream& operator<<(ostream& os, const Biblioteca& b) {
        for (const auto& p : b.items_) os << "  - " << *p << '\n';
        return os;
    }
private:
    vector<unique_ptr<Item>> items_;
};

Simulacro 1 · Ejercicio 2: parking con plazas limitadas (concurrencia, 30 %) monitorsimulacro

Enunciado

Un parking tiene n plazas. Los coches (hilos) llaman a entrar(), que espera si no hay plaza libre, y a salir(). Cuando el parking cierra, ningún coche que espere puede quedarse bloqueado: entrar() devuelve false. Implementa el monitor Parking y un main con 6 coches y 2 plazas que compruebe que nunca hay más de 2 coches dentro.

Antes de empezar: qué piden y qué teoría usas

Qué piden. Un monitor con mutex y condition_variable, una condición de espera con predicado y una condición de cierre.

Teoría que usas. T5: monitor, unique_lock, wait con predicado, notify_one / notify_all, bandera de cierre.

1 1. Estado

libres_ (plazas libres), cerrado_, ocupadas_max_ (para comprobar la invariante) y el mutex.

2 2. entrar y salir

entrar espera con el predicado libres_ > 0 || cerrado_; si se despertó por el cierre, devuelve false sin tomar plaza. salir incrementa bajo el mutex y avisa a uno (hay un solo hueco). cerrar activa la bandera y avisa a todos.

CPPclass Parking {
public:
    explicit Parking(int plazas) : libres_{plazas} {}
    bool entrar() {                                       // false si el parking cerró mientras esperaba
        unique_lock<mutex> lk{m_};
        hay_hueco_.wait(lk, [this] { return libres_ > 0 || cerrado_; });
        if (cerrado_) return false;
        --libres_;
        ocupadas_max_ = max(ocupadas_max_, total_ - libres_);
        return true;
    }
    void salir() {
        { lock_guard<mutex> lk{m_}; ++libres_; }
        hay_hueco_.notify_one();                          // un hueco: despierta a uno
    }
    void cerrar() {
        { lock_guard<mutex> lk{m_}; cerrado_ = true; }
        hay_hueco_.notify_all();                          // el cierre interesa a todos
    }
    int max_ocupadas() { lock_guard<mutex> lk{m_}; return ocupadas_max_; }
private:
    mutex m_;
    condition_variable hay_hueco_;
    int libres_;
    const int total_ = libres_;
    int ocupadas_max_ = 0;
    bool cerrado_ = false;
};
3 3. main
CPPint main() {
    Parking p{2};
    atomic<int> entradas{0};
    vector<thread> coches;
    for (int i = 0; i < 6; ++i)
        coches.emplace_back([&] {
            if (p.entrar()) { ++entradas; this_thread::sleep_for(50ms); p.salir(); }
        });
    for (auto& c : coches) c.join();
    p.cerrar();
    cout << "entradas = " << entradas << '\n';
    cout << boolalpha << "max ocupadas <= 2: " << (p.max_ocupadas() <= 2) << '\n';
    cout << "entrada tras cierre: " << p.entrar() << '\n';
}
4 4. Por qué es correcto
  • Toda lectura/escritura de libres_ y cerrado_ se hace con el mutex tomado.
  • El predicado se vuelve a comprobar tras despertar: un coche que llega de fuera puede quitarte el hueco antes de que reacciones.
  • notify_all en cerrar() + condición || cerrado_: ningún hilo queda dormido para siempre.

Simulacro 2 · Matriz y tarea periódica

Simulacro 2 · Ejercicio 1: clase Matriz con memoria dinámica (POO, 70 %) clasessimulacro

Enunciado

Diseña una clase Matriz de números reales que gestione su propia memoria (double*) con:

  1. Constructor (filas, columnas) con ceros, y acceso m(i, j) (versiones modificable y const).
  2. Regla de los cinco: destructor, constructor de copia (copia profunda), constructor de movimiento y asignación con copy-and-swap.
  3. operator+, operator* (producto), traspuesta() y operator<<. Dimensiones incompatibles → excepción.
  4. Un main que construya A=(123456)A=\begin{pmatrix}1&2&3\\4&5&6\end{pmatrix}A=(14​25​36​), calcule A ATA\,A^TAAT, demuestre que la copia es independiente y capture un error.

Antes de empezar: qué piden y qué teoría usas

Qué piden. Una clase con recursos propios: si no escribes la copia profunda, dos matrices compartirían el mismo double* y se borrarían dos veces.

Teoría que usas. T2: reglas de 0/3/5, copy-and-swap, friend swap, noexcept, operator(), excepciones.

1 1. Memoria y regla de los cinco
  • Constructor: new double[n]{} (inicializa a 0).
  • Copia: reserva nueva y copy.
  • Movimiento: roba el puntero y deja el origen vacío (nullptr, 0×0), para que su destructor no borre lo robado.
  • Asignación por valor + swap: gestiona a la vez la copia y la asignación a uno mismo, y es segura ante excepciones.
CPPclass Matriz {
public:
    Matriz(int filas, int cols) : f_{filas}, c_{cols}, d_{new double[filas * cols]{}} {}
    Matriz(const Matriz& o) : f_{o.f_}, c_{o.c_}, d_{new double[o.f_ * o.c_]} { copy(o.d_, o.d_ + f_ * c_, d_); }
    Matriz(Matriz&& o) noexcept : f_{o.f_}, c_{o.c_}, d_{o.d_} { o.d_ = nullptr; o.f_ = o.c_ = 0; }
    Matriz& operator=(Matriz o) noexcept { swap(*this, o); return *this; }       // copy-and-swap
    ~Matriz() { delete[] d_; }
    friend void swap(Matriz& a, Matriz& b) noexcept { swap(a.f_, b.f_); swap(a.c_, b.c_); swap(a.d_, b.d_); }

    double& operator()(int i, int j) { return d_[i * c_ + j]; }
    double operator()(int i, int j) const { return d_[i * c_ + j]; }
    int filas() const { return f_; }
    int cols() const { return c_; }
2 2. Operaciones

La suma exige mismas dimensiones; el producto, columnas de la izquierda = filas de la derecha. Se acumula en r(i,j) (la matriz resultado empieza en 0).

CPP    Matriz operator+(const Matriz& o) const {
        if (f_ != o.f_ || c_ != o.c_) throw invalid_argument{"dimensiones distintas"};
        Matriz r{f_, c_};
        for (int k = 0; k < f_ * c_; ++k) r.d_[k] = d_[k] + o.d_[k];
        return r;
    }
    Matriz operator*(const Matriz& o) const {
        if (c_ != o.f_) throw invalid_argument{"no se pueden multiplicar"};
        Matriz r{f_, o.c_};
        for (int i = 0; i < f_; ++i) for (int j = 0; j < o.c_; ++j) for (int k = 0; k < c_; ++k) r(i, j) += (*this)(i, k) * o(k, j);
        return r;
    }
    Matriz traspuesta() const {
        Matriz r{c_, f_};
        for (int i = 0; i < f_; ++i) for (int j = 0; j < c_; ++j) r(j, i) = (*this)(i, j);
        return r;
    }
    friend ostream& operator<<(ostream& os, const Matriz& m) {
        for (int i = 0; i < m.f_; ++i) { for (int j = 0; j < m.c_; ++j) os << m(i, j) << (j + 1 < m.c_ ? " " : ""); os << '\n'; }
        return os;
    }
private:
    int f_, c_;
    double* d_;
};
3 3. main
CPPint main() {
    Matriz a{2, 3};
    int v = 1;
    for (int i = 0; i < 2; ++i) for (int j = 0; j < 3; ++j) a(i, j) = v++;
    Matriz b = a.traspuesta();                  // 3x2
    cout << "A:\n" << a << "A^T:\n" << b << "A*A^T:\n" << a * b;
    Matriz c = a;                               // copia profunda
    c(0, 0) = 99;
    cout << "A(0,0) tras modificar la copia: " << a(0, 0) << '\n';
    c = b.traspuesta() + a;                     // asignación (copy-and-swap)
    cout << "A+A:\n" << c;
    try { a * a; } catch (const exception& e) { cout << "error: " << e.what() << '\n'; }
}

Simulacro 2 · Ejercicio 2: tarea periódica y contador compartido (concurrencia, 30 %) hilossimulacro

Enunciado

  1. Escribe un hilo que ejecute 5 veces una tarea cada 20 ms sin acumular deriva (usa sleep_until) y cuenta cuántas veces se ejecutó. Comprueba que la duración total es de unos 100 ms.
  2. Lanza 4 hilos que incrementen 1 000 veces un contador compartido y comprueba que el resultado es 4 000. Usa el mecanismo mínimo adecuado.

Antes de empezar: qué piden y qué teoría usas

Qué piden. Diferenciar sleep_for (deriva) de sleep_until (sin deriva) y proteger un contador con atomic.

Teoría que usas. T4: sleep_until, steady_clock, atomic, join.

1 1. Tarea periódica

El instante siguiente se calcula sumando el periodo al instante teórico anterior, no a now(). Con sleep_for(20ms) cada vuelta duraría 20 ms más lo que tardara el trabajo, y el error se acumularía.

CPPint main() {
    // 1) tarea periódica sin deriva: sleep_until sobre el instante anterior + periodo
    const auto periodo = 20ms;
    int ticks = 0;
    auto inicio = steady_clock::now();
    thread t{[&] {
        auto siguiente = steady_clock::now();
        for (int k = 0; k < 5; ++k) {
            ++ticks;                                    // «trabajo» de la tarea
            siguiente += periodo;                       // se suma al instante teórico, no a now()
            this_thread::sleep_until(siguiente);
        }
    }};
    t.join();
    auto ms = duration_cast<milliseconds>(steady_clock::now() - inicio).count();
    cout << "ticks = " << ticks << '\n';
2 2. Contador compartido

atomic<int> basta: la operación es un incremento simple. Un mutex también valdría, pero es más pesado. Sin protección, el resultado sería menor que 4 000 (demostración de «Pérdida de actualización»).

CPP
    // 2) cuatro hilos suman 1000 veces con atomic
    atomic<int> total{0};
    vector<thread> hilos;
    for (int i = 0; i < 4; ++i) hilos.emplace_back([&] { for (int k = 0; k < 1000; ++k) ++total; });
    for (auto& h : hilos) h.join();
    cout << "total = " << total << '\n';
}
Resultado final

duracion >= 100 ms: true, < 150 ms: true
total = 4000

Simulacro 3 · Planificación

Simulacro 3 · Planificación de tiempo real plansimulacro

Enunciado

Tres tareas periódicas con plazo igual al periodo: τ1\tau_1τ1​ (C=2C=2C=2, T=8T=8T=8), τ2\tau_2τ2​ (C=3C=3C=3, T=12T=12T=12) y τ3\tau_3τ3​ (C=4C=4C=4, T=24T=24T=24).   2. Calcula los tiempos de respuesta (sin bloqueo).
  3. Con el protocolo de techo de prioridad inmediato, calcula los bloqueos BiB_iBi​ y los tiempos de respuesta.
