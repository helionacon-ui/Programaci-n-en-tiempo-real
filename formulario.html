Formulario y chuleta de código

Para qué sirve

Lo que no viene en la hoja de referencia del examen: sintaxis de clases y herencia, concurrencia y las fórmulas de planificación. Es justo lo que puntúa.

Paso de parámetros

  • void f(int x) — por valor, se copia
  • void f(int &x) — por referencia, modifica el original
  • void f(const vector<int> &v) — no copia y no modifica
  • Devolver varios valores: parámetros de salida por referencia
  • Nunca devolver referencia o puntero a una variable local
  • Cada new, un delete; cada new[], un delete[]

STL que más cae

  • s.find(x) → posición o string::npos
  • s.substr(p, n) · stoi(s) · to_string(v)
  • getline(f, linea) · getline(ss, campo, \';\')
  • v.push_back(x) · v.size() · v.empty()
  • m[k]++ para contar (CREA la entrada)
  • m.count(k) / m.find(k) para consultar sin crear
  • sort(v.begin(), v.end(), lambda)
  • Recorrer un map: for (const auto &p : m) → p.first, p.second

Clase bien formada

  • Atributos private, acceso por métodos
  • Lista de inicialización: Punto(double x) : x_(x) {}
  • Métodos de consulta marcados const
  • operator<< como función libre friend que devuelve el flujo
  • Regla de los tres: destructor → también copia y operator=
  • RAII: adquirir en el constructor, liberar en el destructor

Herencia y polimorfismo

  • class Derivada : public Base — relación «es un»
  • Constructor: Derivada(...) : Base(...), x_(x) {}
  • virtual double f() const = 0; — virtual pura → clase abstracta
  • double f() const override en la derivada
  • Destructor virtual en toda base polimórfica
  • Polimorfismo sólo con punteros o referencias (vector<Base*>)
  • Construcción base→derivada; destrucción derivada→base

Hilos

  • thread h(f, arg1, ref(x)); — ref() es obligatorio
  • h.join() o h.detach(), o el programa aborta
  • Método de un objeto: thread h{&C::m, &obj, args};
  • vector<thread> v; v.emplace_back(f, i); for (auto &t : v) t.join();
  • this_thread::sleep_for(chrono::milliseconds(100));
  • Medir: steady_clock::now() y duration_cast<microseconds>
  • Aceleración \(S=T_1/T_p\); Amdahl: \(S\le 1/f\)

Sincronización

  • lock_guard<mutex> lk(m); — RAII, nunca lock/unlock a mano
  • unique_lock<mutex> lk(m); — el que exige wait
  • cv.wait(lk, [this]{ return cond; }); — siempre con predicado
  • Cambiar la condición → unlock → notify_one/all
  • atomic<int> n{0}; ++n; — indivisible sin bloquear
  • Dos mutex: mismo orden siempre, o std::lock(m1, m2)
  • Monitor = datos + mutex + variables de condición en una clase

Planificación clásica

  • \(t_{\text{retorno}}=t_{\text{fin}}-t_{\text{llegada}}\)
  • \(t_{\text{espera}}=t_{\text{retorno}}-t_{\text{CPU}}\)
  • FCFS: orden de llegada, efecto convoy
  • SJF: espera media mínima, pero inanición de los largos
  • Round-Robin: mejor tiempo de respuesta, más cambios de contexto
  • Expulsivo = puede quitar la CPU; en tiempo real, siempre
  • Cambio de contexto ≈ 5 µs

Planificación en tiempo real

  • \(U=\displaystyle\sum C_i/T_i\); necesaria: \(U\le1\)
  • Cota RM: \(U\le n(2^{1/n}-1)\) — suficiente, no necesaria
  • n=2: 0,828 · n=3: 0,780 · n=4: 0,757 · n→∞: 0,693
  • EDF con \(D=T\): planificable sii \(U\le1\)
  • RM: prioridad por periodo · DM: prioridad por plazo
  • Ejecutivo cíclico: \(H=\operatorname{mcm}(T_i)\), \(f\mid T_i\), \(f\ge\max C_i\)
  • Número de marcos \(=H/f\)

Tiempos de respuesta

  • \(R_i=C_i+B_i+\sum_{j\in hp(i)}\left\lceil\frac{R_i}{T_j}\right\rceil C_j\)
  • Iterar desde \(R^{(0)}=C_i+B_i\) hasta que no cambie
  • Cumple si \(R_i\le D_i\)
  • \(\text{techo}(O)=\max\) prioridad de las tareas que usan \(O\)
  • \(B_i=\max\) sección crítica de tarea menos prioritaria con techo \(\ge\) prioridad de \(i\)
  • Con ICPP se bloquea una sola vez: máximo, no suma
  • La tarea menos prioritaria tiene \(B=0\)

Lógica difusa

  • Triangular: \(\mu=\max\left(0,\min\left(\frac{x-a}{b-a},\frac{c-x}{c-b}\right)\right)\)
  • Y → mínimo · O → máximo · NO → \(1-\mu\)
  • Sugeno: \(z^{*}=\dfrac{\sum w_iz_i}{\sum w_i}\)
  • Mamdani: centro de gravedad del conjunto agregado
  • Tres etapas: fuzzificación, inferencia, defuzzificación
  • Cuidado con \(0/0\) si ninguna regla se activa

kNN

  • \(d=\sqrt{\sum (x_j-y_j)^2}\) (euclídea) o \(\sum|x_j-y_j|\) (Manhattan)
  • Normalizar: \(x\'=\dfrac{x-\min}{\max-\min}\) — imprescindible
  • Ordenar por distancia, tomar los \(k\) primeros y votar
  • \(k\) impar con dos clases, para evitar empates
  • Coste \(O(n\cdot d)\) por consulta; entrenamiento nulo
  • Pasar el vector de datos por valor si vas a ordenarlo

Errores que más puntos cuestan

  • Olvidar join() → el programa aborta
  • Olvidar ref() → el hilo recibe una copia
  • wait sin predicado → despertares espurios
  • Olvidar virtual → resultados mal sin aviso
  • Olvidar el destructor virtual → fuga de memoria
  • Usar m[k] para consultar → crea entradas vacías
  • Comparar find con −1 en vez de con npos
  • Sumar los bloqueos en vez de tomar el máximo
