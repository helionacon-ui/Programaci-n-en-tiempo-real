C++ moderno: de los objetos a la concurrencia · Tema 1

Del problema al programa

C++ moderno: de los objetos a la concurrenciaProgramación

Desde cero

Objetivo: organizar el desarrollo de un programa, manejar con soltura los tipos, la memoria y las funciones de C++, y escribir algoritmos correctos desde el principio.

  • Antes de escribir una línea de código hay dos pasos: entender el problema y diseñar la solución. El ciclo completo es análisis → diseño → codificación → pruebas → despliegue → ejecución → modificación, y se repite. El error más caro de un programador novato es empezar por la codificación.
  • Una cosa es saber resolver un problema y otra que esa forma de resolverlo sea expresable en un programa. Hay que pensar la solución con las abstracciones que ofrece el lenguaje.
  • C++ es un lenguaje compilado y de tipado estático: el compilador comprueba los tipos antes de ejecutar nada. Esto detecta muchos errores pronto, a cambio de obligar a declararlo todo.
  • La memoria de un programa tiene dos zonas que hay que distinguir siempre: la pila (stack), donde viven las variables locales y que se libera sola al salir del ámbito, y el montón (heap), donde vive lo reservado con new y que hay que liberar con delete. Todo lo que puedas poner en la pila, ponlo en la pila.
  • Hay tres maneras de pasar un argumento a una función: por valor (se copia; cambiarlo no afecta al original), por referencia (int&: es el mismo objeto con otro nombre) y por referencia constante (const string&: no se copia pero no se puede modificar). La última es la forma correcta de pasar objetos grandes que sólo se leen.
  • Una referencia es un alias: se inicializa al declararla y no se puede reasignar. Un puntero es una variable que guarda una dirección: puede ser nulo, puede reasignarse y hay que desreferenciarlo con *. En C++ moderno se usan referencias casi siempre y punteros sólo cuando hace falta representar «puede que no haya nada».
  • Para devolver varios valores desde una función se usan parámetros de salida por referencia (o se devuelve una estructura). Esto será importante en concurrencia: la función que ejecuta un hilo devuelve void, así que sus resultados salen por referencia.
  • Un programa se escribe para que lo lea otra persona: nombres con significado, funciones cortas, una responsabilidad por función y constantes con nombre en vez de números sueltos.

Explicación ampliada

Qué hace C++ por ti y qué no

C++ es un lenguaje compilado: escribes .cpp, el compilador lo traduce a un programa que la máquina ejecuta directamente, y por eso es rápido y se usa en sistemas de tiempo real. La contrapartida: tú controlas la memoria. Cada variable local vive en la pila (stack) y desaparece sola al acabar su bloque; lo que pides con new vive en el montón (heap) y solo se libera con delete. Regla de oro: cada new, exactamente un delete (y new[] con delete[]). Si te olvidas, hay una fuga de memoria; si lo haces dos veces, el programa falla.

Paso de parámetros: valor, referencia y const

Cuando llamas a una función, ¿qué recibe? Por valor (void f(int x)) recibe una copia: lo que haga con ella no afecta al original. Por referencia (void f(int &x)) recibe un alias del original: lo modifica. Por referencia constante (const string &s) recibe un alias pero sin permiso de cambiarlo: es la forma habitual de pasar objetos grandes sin copiarlos y sin riesgo. El tamaño de cada tipo importa para calcular memoria: char 1 byte, int 4, double 8 (en el sistema típico de 64 bits), así que un array de \(n\) elementos ocupa \(n\cdot\text{sizeof(tipo)}\) bytes.

Desarrollo teórico a fondo

1Un sistema en tiempo real

Idea clave. un sistema de tiempo real es aquel en el que el resultado correcto depende del valor lógico y también del instante en que se produce. Llegar tarde equivale a fallar.
  • Tiempo real estricto (hard): un plazo perdido es un fallo grave (frenos, airbag).
  • Tiempo real firme (firm): el resultado tardío no sirve, pero el sistema sigue.
  • Tiempo real blando (soft): el retraso degrada la calidad, sin fallo crítico (vídeo).
∴Del problema al programa
  1. Define el problema y sus entradas, salidas y plazos.
  2. Descompón en tareas con su periodo y plazo.
  3. Escribe el código con los tipos y la estructura adecuados.
  4. Verifica el comportamiento temporal, no solo el funcional.
Cuidado. Un programa correcto en resultados puede ser incorrecto en tiempo real si una tarea tarda más que su plazo.

Fórmulas y conceptos que hay que saber

  • Estructura mínima:
#include <iostream> using namespace std; int main() { cout << "Hola" << endl; return 0; }
  • Tipos fundamentales: bool · char (1 byte) · int (4) · long (8) · float (4) · double (8) · size_t (sin signo, para tamaños e índices).
  • Paso de parámetros:
void por_valor (int x); // copia void por_referencia (int &x); // alias: modifica el original void solo_lectura (const string &s);// no copia y no modifica
  • Memoria dinámica: int *p = new int(5); ... delete p; · arrays: new int[n] / delete[] p. Cada new necesita exactamente un delete.
  • Bucle for de rango (C++11), el que se usa casi siempre:
for (const auto &x : v) cout << x << " "; for (auto &x : v) x *= 2; // modifica los elementos
  • auto: deduce el tipo. auto it = v.begin(); evita escribir el tipo del iterador.
  • Complejidad de los algoritmos básicos: búsqueda lineal \(O(n)\) · búsqueda binaria \(O(\log n)\) · ordenación eficiente \(O(n\log n)\) · bucle doble \(O(n^2)\).

Método paso a paso

  1. Entiende el problema y escribe a mano un par de casos de ejemplo con su resultado esperado. Serán tus pruebas.
  2. Diseña la solución en pasos, antes de teclear: qué datos hacen falta, en qué estructura se guardan y qué funciones los transforman.
  3. Escribe funciones pequeñas, una por tarea, con nombres que digan lo que hacen.
  4. Decide el paso de parámetros: ¿sólo lo lees? const T&. ¿Lo modificas? T&. ¿Es un tipo pequeño que copias? por valor.
  5. Compila a menudo y lee el primer error, no el último: los demás suelen ser consecuencia.
  6. Prueba con los casos límite: vector vacío, un solo elemento, valores negativos, fichero inexistente.

Trampas típicas

  • Pasar un vector o un string grande por valor sin querer: se copia entero en cada llamada.
  • Devolver una referencia o un puntero a una variable local. Al salir de la función esa memoria ya no es válida.
  • Olvidar el delete de cada new, o hacer delete dos veces.
  • Confundir = (asignación) con == (comparación) dentro de un if.
  • Usar int para indexar un contenedor y comparar con size(), que es size_t (sin signo): el compilador avisa y el bucle puede fallar con contenedores vacíos.
  • Escribir un bucle for (int i=0; i<=v.size(); i++): el último índice válido es size()-1.

Problema resuelto

Enunciado

Escribe una función que reciba un vector de enteros y devuelva, sin usar la biblioteca estándar de algoritmos, el máximo, el mínimo y la media. Después, una versión que además diga cuántos valores están por encima de la media.

Decide bien el paso de parámetros y razona la complejidad.

✓Ver solución paso a paso

1) La firma. El vector sólo se lee: const vector<int> &. Hay que devolver tres valores, así que salen por referencia:

void estadisticas(const vector<int> &v, int &maximo, int &minimo, double &media) { if (v.empty()) { maximo = minimo = 0; media = 0.0; return; } maximo = minimo = v[0]; long suma = 0; // long para no desbordar for (int x : v) { if (x > maximo) maximo = x; if (x < minimo) minimo = x; suma += x; } media = static_cast<double>(suma) / v.size(); }

Tres detalles que valen puntos: el caso vacío tratado al principio; la suma en long para no desbordar; y el static_cast<double> antes de dividir, porque suma / v.size() con dos enteros haría división entera y la media saldría truncada.

2) Contar los que superan la media.

int por_encima(const vector<int> &v) { int maximo, minimo; double media; estadisticas(v, maximo, minimo, media); int n = 0; for (int x : v) if (x > media) ++n; return n; }

3) Complejidad. La primera función recorre el vector una vez: \(O(n)\) en tiempo y \(O(1)\) en memoria adicional. La segunda hace dos pasadas, que sigue siendo \(O(n)\): dos pasadas no son peor orden que una. Lo que sí sería peor es, para cada elemento, recorrer el vector entero para calcular la media: eso sería \(O(n^2)\) y es el error típico.

Comprobación con \(v=\{4,8,15,16,23,42\}\): suma 108, media 18, máximo 42, mínimo 4, y hay 2 valores por encima de la media (23 y 42). Antes de dar por bueno un algoritmo, pásale un caso que puedas comprobar a mano.

Ejercicios resueltos

Intenta cada uno antes de desplegar la solución.

Ejercicio 1 · Memoria de un array

¿Cuántos bytes de datos ocupan int a[1000] y double d[50]?

✓Ver solución paso a paso

\(1000\cdot4=4000\) bytes y \(50\cdot8=400\) bytes (sin contar cabeceras de vector, que son pocos bytes más).

Ejercicio 2 · Valor frente a referencia

void f(int x)  { x += 5; }
void g(int &x) { x += 5; }
int main() { int a = 1, b = 1; f(a); g(b); cout << a << " " << b; }

¿Qué escribe?

✓Ver solución paso a paso

f trabaja con una copia: \(a\) sigue valiendo 1. g modifica el original: \(b=1+5=6\). Salida: 1 6.

Ejercicio 3 · Fugas y delete[]

int *p = new int[5];
int *q = new int(7);
delete p;

¿Qué dos errores hay y cómo se corrigen?

✓Ver solución paso a paso

(1) p se reservó con new[], así que se libera con delete[] p; delete p es comportamiento indefinido. (2) q nunca se libera: fuga de memoria de 4 bytes; falta delete q;. Con 2 new hacen falta exactamente 2 liberaciones.

Autoevaluación

Responde antes de desplegar.

1¿Cuáles son las fases del desarrollo de un programa?

Análisis, diseño, codificación, pruebas, despliegue, ejecución y modificación. La codificación es sólo una de ellas.

2¿Qué diferencia hay entre la pila y el montón?

La pila guarda variables locales y se libera sola al salir del ámbito; el montón guarda lo reservado con new y hay que liberarlo con delete.

3¿Cómo se pasa un objeto grande que sólo se lee?

Por referencia constante: const vector<int> &v. No se copia y no se puede modificar.

4¿Qué diferencia hay entre una referencia y un puntero?

La referencia es un alias: se inicializa al declararse y no se reasigna. El puntero guarda una dirección, puede ser nulo y puede reasignarse.

5¿Cómo devuelve varios valores una función en C++?

Con parámetros de salida por referencia, o devolviendo una estructura. Es lo que se usa en los hilos, porque su función devuelve void.

6¿Por qué suma / v.size() puede dar un resultado equivocado?

Porque si los dos son enteros se hace división entera y se trunca. Hay que convertir uno a double antes.
