Tiempo real: planificación y algoritmos · Tema 8

Planificación en tiempo real: RM, DM, EDF y ejecutivo cíclico

Tiempo real: planificación y algoritmosTiempo real

Desde cero

Objetivo: modelar un sistema de tareas periódicas, asignar prioridades, comprobar si el sistema es planificable y construir un ejecutivo cíclico.

  • Un sistema de tiempo real no es un sistema rápido: es un sistema en el que un resultado correcto fuera de plazo es un resultado incorrecto. Si incumplir el plazo es catastrófico se habla de tiempo real estricto (hard); si sólo degrada la calidad, laxo (soft).
  • Una tarea se modela con cuatro números: el periodo \(T\) (cada cuánto se activa), el tiempo de cómputo \(C\) en el peor caso, el plazo \(D\) (cuándo debe haber terminado desde su activación) y la prioridad. Una tarea es periódica si se activa exactamente cada \(T\), y esporádica si \(T\) es sólo la separación mínima entre activaciones.
  • La utilización \(U=\sum C_i/T_i\) es la fracción de CPU que consume el conjunto. Si \(U>1\) no hay nada que hacer: el sistema no es planificable con ningún algoritmo.
  • Rate Monotonic (RM) asigna prioridades fijas por periodo: a menor periodo, mayor prioridad. Es óptimo entre los algoritmos de prioridad fija cuando \(D_i=T_i\).
  • Deadline Monotonic (DM) asigna prioridades por plazo: a menor \(D\), mayor prioridad. Es la generalización de RM y es la óptima cuando \(D_i\le T_i\). Es el método que piden los exámenes, con el nombre de «prioridades fijas monotónicas en plazo».
  • Earliest Deadline First (EDF) es de prioridad dinámica: en cada instante ejecuta la tarea cuyo plazo absoluto esté más cerca. Es óptimo entre todos los algoritmos y, con \(D_i=T_i\), basta con \(U\le1\) para garantizar el sistema. A cambio, su comportamiento en sobrecarga es impredecible y es más costoso de implementar.
  • La cota de Liu y Layland da una condición suficiente pero no necesaria para RM: si \(U\le n(2^{1/n}-1)\), el sistema es planificable. Esa cota baja de 1 (n = 1) a 0,693 (n → ∞). Si no se cumple, el sistema todavía puede ser planificable: hay que hacer el análisis de tiempos de respuesta del tema siguiente.
  • El ejecutivo cíclico es la alternativa sin sistema operativo: un único bucle que llama a las tareas en un orden fijo, calculado de antemano. No hay concurrencia real, ni hilos, ni interbloqueos; a cambio es rígido y cualquier cambio obliga a recalcular el esquema.
  • Para construirlo se calculan el hiperperiodo (mínimo común múltiplo de los periodos, tras el cual el esquema se repite) y el ciclo menor o frame, que debe dividir a todos los periodos, ser mayor o igual que el mayor \(C_i\) y no superar los plazos. El hiperperiodo dividido entre el ciclo menor da el número de marcos del esquema.
  • Ventajas del ejecutivo cíclico: determinista, sencillo de verificar, sin sobrecarga del sistema operativo y sin problemas de exclusión mutua. Inconvenientes: rígido, obliga a trocear las tareas largas, no admite tareas esporádicas con facilidad y los periodos tienen que ser armónicos para que el esquema sea manejable.

Fórmulas y conceptos que hay que saber

  • Utilización: \(U=\displaystyle\sum_{i=1}^{n}\frac{C_i}{T_i}\). Condición necesaria: \(U\le1\).
  • Cota de Liu y Layland (RM), suficiente:
\[U\le n\left(2^{1/n}-1\right)\]
n1234510→∞
Cota1,0000,8280,7800,7570,7430,7180,693
  • EDF: con \(D_i=T_i\), planificable si y sólo si \(U\le1\). Es una condición necesaria y suficiente.
  • Asignación de prioridades: RM → menor \(T\), mayor prioridad. DM → menor \(D\), mayor prioridad.
  • Ejecutivo cíclico:
\[H=\operatorname{mcm}(T_1,\dots,T_n),\qquad f \mid T_i\ \ \forall i,\qquad f\ge\max C_i,\qquad \text{n.º de marcos}=\frac{H}{f}\]
  • Una elección cómoda y frecuente es \(f=\operatorname{mcd}(T_1,\dots,T_n)\). En cada marco que empieza en \(t\) se ejecutan las tareas con \(t \bmod T_i=0\), y la suma de sus \(C_i\) debe caber en \(f\).
  • Esqueleto del código:
const int F = 40; // ciclo menor en ms int marco = 0; while (true) { auto t0 = steady_clock::now(); if (marco % 1 == 0) f_a(); // T_A = 40 ms -> todos los marcos if (marco % 2 == 0) f_b(); // T_B = 80 ms -> uno de cada 2 if (marco % 3 == 0) f_c(); // T_C = 120 ms -> uno de cada 3 marco = (marco + 1) % 6; // 6 marcos = hiperperiodo 240 ms this_thread::sleep_until(t0 + milliseconds(F)); }

Método paso a paso

  1. Calcula \(U\). Si \(U>1\), el sistema no es planificable y has terminado.
  2. Asigna prioridades según el método que pida el enunciado: RM por periodo, DM por plazo.
  3. Aplica la cota de Liu-Layland si es RM con \(D=T\). Si se cumple, está garantizado; si no, no concluyas que falla: pasa al análisis de tiempos de respuesta.
  4. Para EDF con \(D=T\), basta comparar \(U\) con 1.
  5. Para el ejecutivo cíclico: hiperperiodo con el mcm, ciclo menor con el mcd (comprobando que cabe la tarea más larga), número de marcos, y tabla de qué se ejecuta en cada uno.
  6. Comprueba que la carga de cada marco no supera el ciclo menor y que cada tarea aparece con su periodicidad.

Trampas típicas

  • Concluir que un sistema no es planificable porque no cumple la cota de Liu-Layland. Es una condición suficiente, no necesaria: con \(U=0{,}9\) y periodos armónicos el sistema puede ir perfectamente.
  • Usar RM cuando los plazos son menores que los periodos. Ahí la óptima es DM.
  • Olvidar que la utilización usa el periodo, no el plazo.
  • Elegir un ciclo menor que no divide a algún periodo: entonces las activaciones se desfasan y el esquema no se repite.
  • Elegir un ciclo menor más corto que la tarea más larga: no cabe y habría que trocearla.
  • Decir que EDF es siempre mejor. Es óptimo en condiciones normales, pero en sobrecarga su degradación es impredecible, mientras que con prioridades fijas se sabe exactamente quién falla primero: la tarea menos prioritaria.

Problema resuelto

Enunciado

Un sistema tiene tres tareas periódicas: \(T_A=(T{=}40,\ C{=}10)\), \(T_B=(80,\ 8)\) y \(T_C=(120,\ 12)\) ms, con \(D_i=T_i\).

  1. ¿Es planificable con Rate Monotonic?
  2. ¿Y con EDF?
  3. Construye un ejecutivo cíclico: hiperperiodo, ciclo menor, marcos y código.
✓Ver solución paso a paso

1) Rate Monotonic. Prioridades por periodo: \(T_A\) (40 ms) la más alta, después \(T_B\) (80) y \(T_C\) (120).

\[U=\frac{10}{40}+\frac{8}{80}+\frac{12}{120}=0{,}25+0{,}10+0{,}10=\boxed{0{,}45}\]

La cota para \(n=3\) es \(3(2^{1/3}-1)=0{,}7798\). Como \(0{,}45\le0{,}7798\), el sistema está garantizado con RM. Además la CPU queda libre más de la mitad del tiempo.

2) EDF. Con \(D_i=T_i\) la condición es \(U\le1\), y \(0{,}45\le1\): planificable, como era de esperar. Si ya lo es con RM, lo es con EDF, porque EDF es óptimo.

3) Ejecutivo cíclico.

\[H=\operatorname{mcm}(40,80,120)=\boxed{240\ \text{ms}},\qquad f=\operatorname{mcd}(40,80,120)=\boxed{40\ \text{ms}}\]

Comprobaciones: \(f=40\) divide a los tres periodos ✓ y \(f\ge\max C_i=12\) ✓. El número de marcos es \(240/40=\boxed{6}\).

En cada marco se ejecutan las tareas cuya activación cae en ese instante (\(t \bmod T_i=0\)):

El marco 0 es el peor caso, con 30 ms de los 40 disponibles. Comprobación de periodicidad: A aparece en los 6 marcos (cada 40 ms ✓), B en los marcos 0, 2 y 4 (cada 80 ms ✓) y C en los marcos 0 y 3 (cada 120 ms ✓).

#include <thread> #include <chrono> using namespace std; using namespace std::chrono; void f_a(); void f_b(); void f_c(); int main() { const auto F = milliseconds(40); int marco = 0; auto siguiente = steady_clock::now(); while (true) { if (marco % 1 == 0) f_a(); // cada 40 ms if (marco % 2 == 0) f_b(); // cada 80 ms if (marco % 3 == 0) f_c(); // cada 120 ms marco = (marco + 1) % 6; // 6 marcos = 240 ms siguiente += F; this_thread::sleep_until(siguiente); // espera hasta el instante exacto } }

El sleep_until sobre un instante acumulado, y no un sleep_for(40ms), es importante: si durmiéramos 40 ms después del trabajo, el periodo real sería 40 ms más lo que tardasen las tareas, y el error se acumularía marco a marco.

Lo que hay que saber decir sobre el ejecutivo cíclico: es determinista (el esquema se conoce de antemano y se puede verificar), no necesita sistema operativo ni hilos, y al no haber concurrencia real no hay exclusión mutua ni interbloqueos. A cambio es rígido: cualquier cambio obliga a recalcular el esquema, una tarea más larga que el ciclo menor hay que trocearla a mano, y las tareas esporádicas sólo encajan reservándoles hueco en cada marco.

Autoevaluación

Responde antes de desplegar.

1¿Qué es un sistema de tiempo real?

Uno en el que un resultado correcto pero fuera de plazo es un resultado incorrecto. No significa rápido, significa predecible.

2¿Qué diferencia hay entre RM y DM?

RM asigna prioridades por periodo y DM por plazo. Coinciden cuando \(D_i=T_i\); si \(D_i<T_i\), la óptima es DM.

3¿Qué dice la cota de Liu y Layland y qué no dice?

Que si \(U\le n(2^{1/n}-1)\) el sistema es planificable con RM. No dice lo contrario: si no se cumple, puede seguir siéndolo.

4¿Cuál es la condición de planificabilidad de EDF?

Con \(D_i=T_i\), \(U\le1\), y es necesaria y suficiente.

5¿Cómo se eligen el hiperperiodo y el ciclo menor?

El hiperperiodo es el mcm de los periodos; el ciclo menor debe dividir a todos ellos y ser mayor o igual que el mayor tiempo de cómputo.

6¿Qué ventajas e inconvenientes tiene el ejecutivo cíclico?

Determinista, verificable y sin problemas de exclusión mutua; pero rígido, obliga a trocear tareas largas y encaja mal las esporádicas.
